机场 DNS 报错先查什么？把节点域名和网站域名分开

王牌飞行员2026-09-21— 次阅读
网络体验

本文含推广链接，相关信息与选购建议供你核对；未进行付费套餐实测。

看到“解析失败”就把所有 DNS 改成同一个地址，可能让问题更难定位。代理连接至少会遇到两个不同的名字：你要连接的节点服务器，以及最终访问的网站。先知道哪一步失败，再看对应配置。

两个名字对应两种任务

节点服务器的域名需要先解析，客户端才可能与它建立连接。目标网站的域名则属于后续访问任务，其解析可能由客户端、系统或其他组件参与。具体路径取决于所使用的软件与配置，不能只看系统 DNS 一处。

mihomo 官方 DNS 文档提供普通解析、代理服务器解析及不同处理模式等配置项，说明这些职责可以分开设置。本文不提供适用于所有订阅的一键参数。

从错误文字开始分类

观察到的现象 首先核对
节点服务器域名无法解析 节点信息、配置中的服务器解析方式
节点已连接，某网站解析失败 目标域名相关解析与分流记录
浏览器失败，其他应用正常 浏览器独立 DNS 或代理设置
改配置后全面异常 恢复原配置，再逐项比较

日志中显示的测试地址也可能不是你当前访问的网站。记录完整错误类型与发生时间，但不要公开其中的订阅凭据。

Fake-IP 为什么不能只凭地址判错

mihomo 文档列出 fake-ip 与 redir-host 两种处理模式。采用 Fake-IP 时出现用于映射的地址，并不能仅凭“不是目标网站真实地址”就判定故障。是否正常，需要结合配置模式和实际请求结果来检查。

给新手的四步顺序

先保存原配置；复现一个具体失败任务；定位报错涉及的域名与组件；再按照所用客户端的官方说明改动最小的一项。修改后重复同一任务，并确认原来正常的访问没有被破坏。

如果自己无法解释配置，应把脱敏后的错误与版本信息发给服务方支持，而不是复制一大段不明来源的 DNS 模板。选机场时，清楚的配置说明与可用的支持渠道，也是值得核对的条件。
